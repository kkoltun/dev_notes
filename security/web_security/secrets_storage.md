# Secrets storage

## Hash or encrypt?

* **You only verify the value** = hash it. You compare what comes in against what you stored, you never need the
  original back.
* **You need to use the value** = encrypt it. You have to present the original to someone else, so it must be
  recoverable.

With encryption the key becomes the thing to protect. It has to live outside the database (KMS, secrets manager,
environment variable), otherwise a database leak hands over both the ciphertext and the key.

## Salt and slow hash - when?

Both protect secrets that are **guessable**.

* `Salt` = a random value stored per user and hashed together with the password. Without it an attacker can hash the
  most popular passwords once and match them against all the users. It also hides which users share a password.
* `Slow hash` (bcrypt, argon2) = makes every single guess expensive.

A long random value generated by the server (e.g. an access token) is not guessable, so it needs neither - a fast
SHA-256 is enough. Also, with an unsalted hash you can find the row directly by the hash.

### Where the salt is stored

The salt is not secret, and bcrypt keeps it inside the hash string, so one column is enough:

```
$2a$10$N9qo8uLOickgx2ZMRZoMyeIjZAgcfl7p92ldGxad68LJZdL17lhWy
 2a                         - algorithm version
    10                      - cost: 2^10 rounds
       N9qo8uLOickgx2ZMRZoMye - salt, 22 chars (16 random bytes)
       the remaining 31 chars - the hash
```

* `encode(password)` generates a random salt, runs bcrypt with it and returns version + cost + salt + hash as one string.
* `matches(typed, stored)` reads the version, cost and salt from the stored string, runs bcrypt on the typed password
  with them and compares the result with the hash part.

The cost travels with each hash, so it can be raised for new passwords while the old hashes still verify.

## Example

Woodpecker is an OAuth2 `client` that accesses Google mailboxes, see [OAuth2 notes](oauth2.md).

| Who                             | Secret                                   | Stored as                         | Why                                                                                 |
|---------------------------------|------------------------------------------|-----------------------------------|-------------------------------------------------------------------------------------|
| Woodpecker                      | Users' Woodpecker passwords              | Salted slow hash (bcrypt, argon2) | Only verified at login. Salted, because passwords are guessable.                    |
| Woodpecker (`client`)           | Google access/refresh tokens per mailbox | Encrypted                         | The original value must be sent to Google on every call.                            |
| Woodpecker (`client`)           | Its own `client_secret`                  | Encrypted or in a secrets manager | The original value must be sent to Google on every code exchange.                   |
| Google (`authorization server`) | Tokens it issued                         | Fast hash (SHA-256), no salt      | Only compared with incoming tokens. No salt, because tokens are long random values. |
